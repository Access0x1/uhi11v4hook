# docs/feedback/ — one file per partner

The root `FEEDBACK.md` is the primary partner's file, at the root because that
partner's rules require it there by name. Every other partner whose tools this project
touches gets its own file here, named `<partner>.md`, in exactly the same four-part
entry format, and is linked from the table at the bottom of the root file.

The rules are the root file's rules:

- captured the hour it happens, never reconstructed;
- four parts per entry — trying to, blocked by, cost, would have prevented it;
- literal errors, exact URLs, exact versions, honest time;
- written so a maintainer could open a PR without a follow-up question;
- no prizes, no strategy, no comparison between partners.

A partner whose tools were investigated but not used gets a file that says exactly
that — what was tried, what was found, why it was not adopted — because a stated
negative is useful to a maintainer and an absent file is not.

Companion journal for the intention behind each integration: `BACKFEED.md` at the
root.
